One source of truth for every value on the site.
Built, synced, verified — before a single line of CSS is written.

The promise

Design and code, in sync. Values flow from the token source to the site through one loop — no manual copies, no drift, no literal slipping in unnoticed.

Orin Tokens (mirror)

Five collections in the Orin team, generated from the JSON. Never the origin: edit here and the two drift.

Synced view
The check points back up the arrow

check:figma diffs the mirror against tokens/src/, values and descriptions both, and exits non-zero on any disagreement. It names two readings because it cannot tell which way truth flows in the repo it is pointed at. Here it is the second one: a failure means somebody edited a generated file, which is a defect rather than a signal to sync.

Two honest limits

The check lives in the Orin Token Pipeline repo, not this one, because that is where the Figma read path already is; it matches collections by name, so the same command points at a client file or at this mirror. And the forward arrow is still manual: the JSON → Figma write automation is unbuilt, so re-mirroring is a person's job.

What this gives you

Consistency

One value, one place. The page cannot disagree with the source.

Efficiency

No manual exports, no copy-paste between design and code.

Reliability

A hardcoded hex fails the report before it ever reaches the site.

Scalability

Dark mode is authoring, not a retrofit — the site reads semantics.

Developer-ready

Plain CSS custom properties. No framework to adopt.

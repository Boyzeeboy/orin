The rule

Sink first, then Sync. The plugin POSTs to a listener. If it is not already running, Sync gets connection refused and nothing says so.

Read the audit out loud before applying anything. The dry-run writes nothing, and it is the whole conversation.

If it goes wrong
✗ No dump at tokens/.figma-dump.json

The sink was not listening when Sync was pressed. Start the sink, press Sync again, then re-run. Since the dumps were cleared, this error is the safety net rather than a nuisance.

The audit looks like yesterday's

A stale dump. Did the sink print ✓ wrote N bytes? If not, nothing new landed and you are reading the last fetch.

No Onkey plugin in the menu

Plugins → Development → Import plugin from manifest… → on-key/plugin/manifest.json. The scaffold made a new plugin Figma has never seen.

Few or no collections found

Probably a consuming file rather than the library. getLocalVariablesAsync returns local variables only. Looks like a damning finding; it is the wrong file.

Plugins menu greyed out

View-only access. Plugins need edit rights. Duplicate to your own drafts and run it there — and say so, because not touching their file is worth saying.

sink listening on 9231

Wrong repo. That is Synthesis or the baseline. Onkey is 9232.

Rehearsing the gates · on a duplicate only
Never in their file
White on brand · late and quiet, fails at the build

Semantic collection, colour/text/on-brand, raw hex FFFFFF typed into both modes. Not an alias: every sibling row aliases a primitive, and a primitive flips per mode. A literal cannot. Sink, Sync, dry-run shows +1 added and raises nothing; npm test then fails naming --onkey-colour-text-on-brand. The sync checks structure; the gate is in the build. Whether it is a real defect depends on their palette — white on brand is only wrong if the brand lightens for dark. On Synthesis it fell from 5.43:1 to 2.73:1.

A name collision · early and loud, fails at the sync

One variable named X/DEFAULT where X already exists. The uppercase sentinel is stripped on exact match, so both resolve to the same emitted name and npm run sync:figma throws before writing anything, naming every collision at once as Figma names. Running both tells you which half of the pipeline caught what, which is what a developer in the room will ask.

Undo

git checkout tokens/ dist/, clear the dumps, and delete the variable in Figma — otherwise the next sync brings it straight back.

What the checks cannot do

The plugin resolves aliases inside Figma before anything leaves the machine, so by the time any check runs, a reference and a hard-typed hex look identical. The pipeline can prove the two themes differ. It cannot prove the semantics are wired to the primitives.

Reading the file is still a person's job, and that is the honest half of what the two weeks buys: a generated audit produces evidence, not conclusions.
